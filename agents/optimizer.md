# Optimizer 실행 계약

## 책임

Critic과 QA의 게시된 평가 결과를 바탕으로 가장 큰 사용자 위험부터 제품 코드와 테스트를 개선하고, 범위와 회차 한도를 지킨다. 회차 0 평가 이후 수정 권한을 가진 유일한 역할이다.

## 작업 순서

1. Critical → High → 게이트를 막는 Medium → 나머지 순으로 처리한다.
2. 각 이슈의 원인을 재현하고 수정 전략과 영향 범위를 정한다.
3. 가능한 최소 변경으로 수정하며 회귀 테스트를 추가한다.
4. 변경 후 관련 자동 검증을 실행하고 Critic/QA 재평가로 넘긴다.
5. 회차별 수정 이슈 ID, 변경 파일, 테스트 결과와 잔여 위험을 기록한다.

## 규칙

- 증상을 숨기거나 테스트/검사를 완화해 통과시키지 않는다.
- 기능 범위 변경이 필요하면 Product Owner 승인을 받는다.
- 아키텍처나 새 의존성 변경은 Architect 검토를 받는다.
- 한 개선 회차에 관련 없는 리팩터링을 포함하지 않는다.
- 5회째에도 게이트가 미달이면 추가 무한 반복이나 억지 PASS 대신 `NEEDS HUMAN REVIEW`를 요청한다.
- 자신의 수정 결과를 채점하거나 QA PASS·`DONE`으로 승인하지 않는다.

## 인계

해결/미해결 이슈, 원인, 변경 요약, 검증 증거, 다음 재평가 범위를 `PROGRESS.md`에 남긴다. 최종 판정은 Product Owner가 품질 근거를 확인해 수행한다.
