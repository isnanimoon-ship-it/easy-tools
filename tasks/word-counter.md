# Word Counter SPEC

## 문서 상태

- 기능명: 글자수 계산기 (Word Counter)
- 상태: `SPEC READY`
- 우선순위: 첫 번째 유틸리티 / P0
- Product Owner 승인일: 2026-08-26
- 개선 회차: 최초 구현 전
- 예정 URL: `/{locale}/tools/word-counter`
- 지원 locale: `ko`, `en`, `ja`

## 1. 문제 정의

사용자는 문서나 게시물의 분량을 확인하기 위해 텍스트의 글자, 공백 제외 글자, 단어, 줄 수를 빠르게 알아야 한다. 기존 도구는 로그인, 서버 전송, 불명확한 계수 규칙 또는 모바일 사용성 문제를 동반할 수 있다.

## 2. 대상 사용자

- 원고·자기소개서·게시물의 분량을 확인하는 사용자
- 모바일에서 작성 중인 텍스트를 즉시 점검하려는 사용자
- 한국어·영어·일본어 텍스트를 서버에 전송하지 않고 분석하려는 사용자

## 3. 가치 제안

텍스트를 붙여 넣거나 입력하면 브라우저 안에서 즉시 네 가지 분량 지표를 명확한 규칙으로 계산한다.

## 4. 포함 범위

- 여러 줄 텍스트 입력
- 전체 글자 수
- 공백 제외 글자 수
- 단어 수
- 줄 수
- 입력과 동시에 실시간 계산
- 입력과 결과를 비우는 초기화
- 모바일 우선 반응형 UI
- `ko`, `en`, `ja` 인터페이스와 locale별 SEO metadata
- 브라우저 내부 처리 및 개인정보 안내

## 5. 제외 범위

- 로그인, 저장, 기록, 클라우드 동기화
- 파일 업로드 및 URL에서 텍스트 가져오기
- 바이트 수, 문장 수, 문단 수, 읽기 시간, 글자 제한 목표
- 맞춤법·문법 검사, 형태소 분석, 키워드 분석
- 결과 복사 또는 내보내기
- 서버 API, 데이터베이스, 외부 분석 서비스

제외 범위의 제안은 현재 기능에 추가하지 않고 `IDEAS.md`에서 별도 검토한다.

## 6. 계수 규칙

### 6.1 전체 글자 수

- 사용자가 인식하는 유니코드 grapheme cluster를 한 글자로 센다. 결합 문자와 피부색 등이 결합된 이모지는 화면에 하나로 보이면 한 글자다.
- 일반 공백, 탭과 줄바꿈을 포함한다.
- Windows 줄바꿈 `CRLF`는 하나의 논리적 줄바꿈 문자로 정규화해 한 글자로 센다. 단독 `CR`과 `LF`도 각각 한 글자다.
- 빈 입력은 0이다.

### 6.2 공백 제외 글자 수

- 전체 글자 수와 같은 문자 단위를 사용한다.
- 유니코드 White_Space에 해당하는 공백, 탭, 줄바꿈을 모두 제외한다.
- 문장부호와 이모지는 제외하지 않는다.

### 6.3 단어 수

- 현재 URL locale을 기준으로 `Intl.Segmenter`의 `word` granularity와 `isWordLike` 의미를 사용한다.
- 공백과 문장부호만으로 된 구간은 단어로 세지 않는다.
- 한국어·영어·일본어처럼 단어 경계 방식이 다른 언어를 동일한 locale 기반 규칙으로 처리한다.
- 빈 입력 또는 공백·문장부호만 있는 입력은 0이다.
- 지원 브라우저에서 `Intl.Segmenter`를 사용할 수 없는 경우 공백으로 분리한 비어 있지 않은 토큰을 fallback으로 사용한다. 이 제한은 도움말에 공개한다.

### 6.4 줄 수

- 빈 입력은 0줄이다.
- 입력이 하나라도 있으면 정규화된 줄바꿈 수 + 1이다.
- `CRLF`, 단독 `CR`, 단독 `LF`를 각각 하나의 줄바꿈으로 취급한다.
- 마지막 문자가 줄바꿈이면 그 뒤의 빈 줄도 한 줄로 센다. 예: `a\n`은 2줄이다.

## 7. 대표 사용자 흐름

1. 사용자가 locale별 독립 URL로 직접 진입한다.
2. 제목, 짧은 설명, 개인정보 안내와 텍스트 입력 영역을 확인한다.
3. 텍스트를 입력하거나 붙여 넣는다.
4. 네 지표가 별도 실행 버튼 없이 즉시 갱신된다.
5. 사용자가 초기화를 누르면 입력과 네 지표가 초기 상태로 돌아가고 입력 영역에 focus가 복귀한다.

## 8. UI 및 상태 요구사항

- 화면 순서: 제목/설명 → 입력 영역과 초기화 → 결과 지표 4개 → 계수 기준/개인정보 안내
- 입력 영역에는 항상 보이는 label과 간단한 설명을 제공하며 placeholder로 label을 대체하지 않는다.
- 초기화는 텍스트가 비어 있을 때 disabled 상태다.
- 결과는 `전체 글자`, `공백 제외`, `단어`, `줄` 레이블과 locale 형식의 정수로 표시한다.
- 초기 상태에서도 네 결과 카드는 모두 0을 표시한다.
- 계산 중 로딩 상태는 두지 않는다. 입력 이벤트와 같은 상호작용 안에서 계산한다.
- 결과 갱신은 시각적으로 즉시 보이되, 스크린 리더에 입력할 때마다 과도한 알림을 발생시키지 않는다. 결과 영역은 의미 있는 그룹과 레이블로 탐색 가능해야 한다.
- 320px 이상에서 가로 스크롤, 겹침, 잘림 없이 사용 가능해야 한다. 모바일에서는 결과를 읽기 쉬운 단일 또는 2열 그리드로 배치하고 초기화 터치 영역은 최소 44px 높이를 확보한다.
- 키보드만으로 입력과 초기화를 사용할 수 있고 focus 표시가 보여야 한다.

## 9. 다국어 및 SEO 요구사항

- 모든 사용자 문구는 `messages/ko.json`, `messages/en.json`, `messages/ja.json`의 동일한 `Tools.wordCounter` namespace에서 관리한다.
- 세 locale에서 제목, 설명, 입력 label/도움말, 결과 레이블, 초기화, 계수 기준, 개인정보 안내를 제공한다.
- 페이지별 고유 title과 description을 제공한다.
- canonical은 현재 locale URL, language alternates는 세 locale의 동일한 `tools/word-counter` 경로를 가리킨다.
- `<h1>`은 페이지에 하나이며 검색 사용자가 기능을 바로 이해할 수 있는 이름을 사용한다.

## 10. 개인정보·보안·성능

- 입력 텍스트는 서버, 외부 API, 분석 서비스로 전송하거나 영구 저장하지 않는다.
- 입력은 HTML로 해석하거나 DOM에 비정제 삽입하지 않는다.
- 네트워크 없이 이미 열린 페이지에서 계산이 계속 가능해야 한다.
- 입력 길이에 인위적인 제한은 두지 않되 100,000 grapheme 수준의 텍스트에서도 UI가 멈추지 않아야 한다.
- QA 기준 장비와 최신 안정 Chrome에서 100,000 ASCII 글자를 붙여 넣은 뒤 결과가 200ms 이내 표시되는 것을 목표로 하며, 측정 환경과 결과를 기록한다. 이는 점수 항목이며 정확성·조작성 실패가 없다면 단독 High 이슈로 분류하지 않는다.

## 11. 수용 기준

1. 빈 입력에서 전체 글자, 공백 제외 글자, 단어, 줄이 모두 0이다.
2. `Hello world`는 전체 11, 공백 제외 10, 단어 2, 줄 1이다.
3. `안녕 세상`은 전체 5, 공백 제외 4, 단어 2, 줄 1이다.
4. `one\ntwo\n`은 전체 8, 공백 제외 6, 단어 2, 줄 3이다.
5. `a\r\nb`는 전체 3, 공백 제외 2, 단어 2, 줄 2로 계산된다.
6. 공백·탭·줄바꿈만 입력하면 전체 글자에는 포함되지만 공백 제외 글자와 단어는 0이다.
7. 결합 문자인 `e` + combining acute accent와 하나로 표시되는 결합 이모지는 각각 전체 글자 한 개로 센다.
8. 일본어 `今日は晴れです`의 단어 수는 현재 locale의 `Intl.Segmenter` 결과와 일치한다.
9. 입력·붙여 넣기·삭제 직후 별도 실행 버튼 없이 네 결과가 현재 값으로 갱신된다.
10. 초기화를 실행하면 텍스트가 비고 네 결과가 0이 되며 입력 영역에 focus가 돌아간다.
11. 빈 입력에서는 초기화가 disabled이고 키보드 및 터치 입력으로 정상 조작된다.
12. 320/375/768/1280px에서 핵심 흐름이 완료되고 의도하지 않은 가로 스크롤·잘림·겹침이 없다.
13. `ko`, `en`, `ja` URL에서 번역 누락 없이 동일 기능이 제공되고 metadata, canonical, language alternates가 올바르다.
14. 정상 흐름과 초기화 흐름에서 Console Error와 처리되지 않은 Promise rejection이 0이다.
15. 입력 텍스트가 어떤 네트워크 요청에도 포함되지 않는다.

## 14. Architect 검토

### 결론

현재 프로젝트 구조와 충돌 없이 구현 가능하다. 기존 App Router, `next-intl`, Tailwind CSS, locale 강제 prefix, 공통 layout/UI 패턴을 그대로 사용할 수 있다.

### 권장 구현 경계

```text
app/[locale]/tools/word-counter/page.tsx
components/tools/word-counter/word-counter.tsx
lib/tools/word-counter/count-text.ts
lib/tools/word-counter/count-text.test.ts
messages/{ko,en,ja}.json            # Tools.wordCounter 추가
```

- 페이지와 metadata는 Server Component에 유지한다.
- 입력 상태와 실시간 상호작용만 작은 Client Component로 격리한다.
- 계수 로직은 React와 분리된 순수 함수로 구현한다.
- 기존 `TextInput`은 단일 행 `<input>` 전용이므로 변경하지 않고, 도구 전용 `<textarea>` 또는 향후 범용 `TextArea`를 사용한다. 첫 사용처뿐인 범용 추상화는 강제하지 않는다.
- 기존 `ResultPanel`은 단일 결과 영역에 가깝다. 네 지표 카드는 도구 전용 구성으로 시작하고 두 번째 확정 사용처 전에는 과도하게 공통화하지 않는다.

### 확인된 비충돌 사항

- `/{locale}/tools/word-counter`는 현재 빈 `app/[locale]/tools` 영역과 충돌하지 않는다.
- `Tools` 메시지 namespace가 현재 비어 있어 `Tools.wordCounter`를 안전하게 추가할 수 있다.
- `strict` TypeScript와 `@/*` alias를 그대로 사용할 수 있다.
- 브라우저 로컬 계산이므로 서버 API나 데이터베이스가 필요 없다.
- `Intl.Segmenter`는 프로젝트의 최신 Chrome 지원 기준과 부합하며 fallback으로 기능 저하를 통제할 수 있다.

### 구현 전 주의사항

- layout의 metadata alternates는 홈 경로를 대상으로 하므로 도구 페이지에서 반드시 자체 metadata와 도구 경로 alternates로 덮어써야 한다.
- 실시간 결과 전체를 `aria-live`로 두면 입력마다 과도한 낭독이 발생할 수 있으므로 결과 구조는 읽을 수 있게 하되 자동 알림은 제한한다.
- 테스트 러너가 아직 없으므로 구현 시 개발 의존성과 명령을 명시적으로 추가해야 한다. 이는 기능 구현에 필요한 최소 기반이며 제품 서버 의존성을 만들지 않는다.
