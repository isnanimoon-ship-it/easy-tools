# 이미지 워터마크 추가 / Image Watermark SPEC

## 문서 상태

- 기능명: 이미지 워터마크 추가 / Image Watermark
- 상태: `DRAFT — Product Owner 승인 대기`
- 작성일: 2026-09-21
- 예정 URL: `/{locale}/tools/image-watermark`
- 지원 locale: `ko`, `en`, `ja`
- 카테고리: 이미지
- 처리 방식: 브라우저 로컬 Canvas 처리
- 현재 단계: 요구사항 및 기술 범위 확정, 구현 미착수
- 구현 기준: 사용자 승인 후 이 문서를 기준으로 개발

## 1. 목적과 사용자 가치

사용자가 사진이나 작업 이미지에 저작자명, 상호, 계정명, 안내 문구 또는 로고를 간단히 배치하고 새 이미지로 내려받게 한다. 별도 편집 프로그램 설치나 회원가입 없이 사용할 수 있어야 하며, 원본 이미지와 워터마크 파일은 서버 또는 외부 API로 보내지 않는다.

이 도구는 워터마크를 제거하거나 저작권을 판별하는 기능이 아니다. 사용자는 자신이 사용할 권한이 있는 이미지와 로고만 사용해야 한다.

## 2. 대상 사용자와 사용 사례

- 커뮤니티나 SNS에 올릴 사진에 계정명을 표시하려는 사용자
- 쇼핑몰 상품 이미지에 상호나 로고를 넣으려는 사용자
- 블로그·포트폴리오 이미지에 출처를 표시하려는 사용자
- 시안 이미지에 `SAMPLE`, `미리보기`, `외부 공유 금지` 문구를 반복해서 넣으려는 사용자
- 별도 디자인 프로그램 없이 투명 로고를 사진 모서리에 배치하려는 사용자

## 3. Product Owner 범위 결정

### Must Have — V1

- 원본 JPG/JPEG, PNG, WebP 정적 이미지 1장 업로드
- Drag & Drop과 파일 선택
- 텍스트 워터마크와 이미지 워터마크 모드
- 실제 결과와 같은 비율을 유지하는 미리보기
- 텍스트 입력, 글꼴 종류, 굵기, 크기, 색상
- 이미지 워터마크 업로드, 비율 유지 크기 조절
- 공통 불투명도, 회전 각도, 가장자리 여백
- 9개 위치 프리셋: 좌상·상단·우상·좌측·중앙·우측·좌하·하단·우하
- 단일 배치와 반복 배치 선택
- 설정 변경 후 결과가 오래된 상태임을 표시
- 명시적인 `워터마크 적용` 실행
- 원본 해상도로 결과 렌더링
- 출력 형식과 JPEG/WebP 품질 선택
- 결과 미리보기, 파일 정보, 다운로드
- 초기화 및 이미지 교체
- 브라우저 로컬 처리 안내
- light/dark theme 및 320px 이상 반응형
- 기존 공통 Hero, Breadcrumb, Share, 상세 콘텐츠 구조 재사용

### Should Have — V1에 포함하되 성능 QA 필수

- 여러 줄 텍스트
- 텍스트 그림자 또는 배경 박스 중 하나 선택
- 워터마크 반복 배치의 가로·세로 간격 조절
- 미리보기 위에서 단일 워터마크를 드래그해 위치 조절
- 위치 프리셋 선택 시 드래그 좌표 초기화
- 설정값 숫자 입력과 range control 동시 제공

드래그 배치는 pointer, keyboard, touch에서 모두 접근 가능해야 한다. 키보드 이동과 모바일 터치가 안정적으로 구현되지 않으면 V1에서는 9개 프리셋과 여백만 제공하고 드래그는 다음 버전으로 미룬다.

### Could Have — 후속 버전

- 여러 원본 이미지 일괄 처리와 ZIP 다운로드
- 사용자 글꼴 파일 업로드
- 워터마크 설정 프리셋 저장

- 날짜·파일명 자동 삽입 변수
- 테두리를 따라 배치하는 패턴

- AVIF, HEIC/HEIF, GIF/APNG/animated WebP

### Do Not Build — V1

- 워터마크 제거
- AI 기반 저작권 판별 또는 이미지 생성
- 클라우드 저장, 공유 링크, 처리 기록
- 이미지 URL 가져오기
- 서버 업로드나 Server Action 이미지 처리
- 원본 파일 덮어쓰기
- 저작권 보호를 100% 보장한다는 표현
- 애니메이션의 모든 프레임 처리

## 4. 핵심 사용자 흐름

1. 사용자가 원본 이미지를 선택하거나 Drag & Drop한다.
2. MIME, signature, 파일 크기, 해상도, 정적 이미지 여부를 검증한다.
3. 이미지 방향을 반영한 미리보기와 원본 정보를 표시한다.
4. `텍스트` 또는 `이미지` 워터마크를 선택한다.
5. 내용, 크기, 색상 또는 로고 파일, 불투명도, 회전, 위치, 여백을 설정한다.
6. 미리보기에서 배치를 확인한다.
7. `워터마크 적용`을 누르면 원본 해상도로 결과를 렌더링한다.
8. 사용자는 결과 형식·해상도·용량을 확인하고 다운로드한다.
9. 설정이 바뀌면 기존 결과는 `이전 설정으로 생성됨` 상태가 되고 다운로드를 비활성화하거나 새 적용을 요구한다.

빈 화면은 오류가 아니다. 원본 이미지가 없을 때 설정과 실행 버튼은 비활성화하고 업로드 안내를 우선 표시한다.

## 5. 지원 형식과 입력 제한

| 구분 | 지원 입력 | V1 처리 |
|---|---|---|
| 원본 이미지 | JPEG, PNG, WebP | 정적 이미지 1장 |
| 이미지 워터마크 | JPEG, PNG, WebP | 투명 PNG/WebP 지원 |
| 출력 | JPEG, PNG, WebP | 브라우저 encoder 지원 범위 |

- 확장자만 신뢰하지 않고 MIME, signature와 실제 decode를 함께 확인한다.
- 원본 이미지 제안 제한: 25 MiB, 최대 24MP, 한 변 최대 12,000px.
- 워터마크 이미지 제안 제한: 10 MiB, 최대 12MP, 한 변 최대 8,000px.
- 제한 수치는 기존 이미지 도구와 모바일 메모리 QA 결과에 따라 더 낮출 수 있다.
- GIF, APNG, animated WebP는 첫 프레임만 조용히 처리하지 않고 애니메이션 미지원 사실을 안내한다.
- SVG는 스크립트·외부 리소스·폰트 처리 위험과 Canvas 호환 차이 때문에 V1에서 지원하지 않는다.
- 손상 파일, 0 byte, MIME/signature 불일치, decode 실패는 파일별로 명확한 오류를 표시한다.

## 6. 텍스트 워터마크 설정

### 입력

- 한 줄 및 여러 줄 텍스트
- 앞뒤 공백은 사용자의 명시적 입력으로 유지하되, 완전히 빈 문자열은 적용 불가
- 최대 500자, 최대 10줄을 제안한다.
- 줄바꿈은 미리보기와 결과에서 동일하게 처리한다.

### 글꼴

V1은 네트워크 다운로드가 필요 없는 시스템 글꼴 계열만 제공한다.

- 고딕: `system-ui, sans-serif`
- 명조: `serif`
- 고정폭: `ui-monospace, monospace`

실제 글꼴 모양은 운영체제에 따라 다를 수 있음을 안내한다. 웹폰트나 외부 폰트를 자동 요청하지 않는다.

### 스타일

- 글꼴 크기: 결과 이미지 짧은 변 대비 비율을 기본 단위로 사용하고 UI에는 예상 px도 함께 표시
- 제안 범위: 짧은 변의 1%~30%, 기본 5%
- 굵기: 보통, 굵게
- 색상: color picker + HEX 입력, 기본 `#ffffff`
- 불투명도: 5%~100%, 기본 70%
- 회전: -180°~180°, 기본 0°
- 선택 효과: 없음 / 그림자 / 배경 박스
- 그림자는 색상·blur를 복잡하게 노출하지 않고 가독성이 확보되는 안전한 기본값을 사용한다.
- 배경 박스는 텍스트 주위 padding과 동일 불투명도 또는 별도 5%~100%를 사용할 수 있다. 구현 복잡도가 커지면 별도 불투명도는 V2로 미룬다.

글꼴 크기를 고정 화면 px로만 저장하지 않는다. 미리보기 축소 배율과 무관하게 결과 이미지에서 같은 상대 크기를 유지해야 한다.

## 7. 이미지 워터마크 설정

- JPEG, PNG, WebP 워터마크 이미지 업로드
- 투명도(alpha)가 있는 PNG/WebP는 투명도를 유지한다.
- 크기: 원본 이미지 짧은 변 대비 5%~80%, 기본 20%
- 원본 종횡비를 항상 유지하며 임의 늘이기·찌그러뜨리기를 제공하지 않는다.
- 불투명도: 5%~100%, 기본 80%
- 회전: -180°~180°, 기본 0°
- 워터마크 이미지 자체의 여백은 원본 파일 픽셀에 포함된 것으로 취급한다.
- JPEG 로고의 흰 배경을 자동 제거하거나 투명하게 만들지 않는다.

워터마크 이미지가 설정되지 않은 경우 실행 버튼을 비활성화하고 텍스트 모드 결과를 대신 사용하지 않는다.

## 8. 위치, 여백과 반복 배치

### 단일 배치

- 3×3 위치 버튼을 제공한다.
- 기본 위치는 우하단이다.
- 가장자리 여백은 원본 이미지 짧은 변 대비 0%~20%, 기본 3%다.
- 중앙 위치에서도 여백 control은 유지하되 결과에는 영향이 없음을 UI로 설명하거나 비활성화한다.
- 회전 후의 bounding box가 Canvas 밖으로 잘리지 않도록 위치 계산은 회전된 외접 영역을 기준으로 한다.

### 반복 배치

- `한 곳에 배치`와 `반복해서 채우기`를 명확히 구분한다.
- 반복 모드는 원본 전체를 일정한 간격으로 덮으며 기본 회전 -30°, 기본 간격은 워터마크 외접 크기의 50%다.
- 반복 모드에서는 9방향 위치 control을 비활성화하고 간격 control을 표시한다.
- 경계 밖에서 시작해 회전 후 모서리에 빈 영역이 과도하게 생기지 않도록 충분한 행·열을 계산한다.
- 최대 타일 개수를 정해 매우 작은 워터마크와 간격 0으로 브라우저가 멈추는 것을 방지한다. 제안 상한은 2,000개다.

### 직접 위치 조절

- 미리보기 좌표는 0~1의 정규화 좌표로 저장하고 실제 결과 크기에 맞춰 환산한다.
- CSS 표시 좌표를 결과 Canvas px로 직접 저장하지 않는다.
- 드래그 종료 후 워터마크 중심이 이미지 밖으로 완전히 나가지 않도록 clamp한다.
- 키보드는 방향키 1단위, Shift+방향키 10단위 이동을 제공한다.

## 9. 미리보기와 실제 결과의 일치

- 미리보기는 원본 종횡비를 유지하고 `object-fit: contain` 영역을 기준으로 그린다.
- 워터마크 배치는 이미지가 실제로 표시된 content rect를 기준으로 하며, container의 빈 여백을 좌표에 포함하지 않는다.
- 미리보기용 저해상도 Canvas와 다운로드용 원본 해상도 Canvas는 동일한 순수 layout 계산 함수를 사용한다.
- 텍스트 줄바꿈, 정렬, 글꼴 크기, 회전 중심, 투명도, 반복 간격을 동일 비율로 환산한다.
- 브라우저별 system font 차이로 글자 폭이 달라질 수 있으며 같은 기기에서 미리보기와 결과는 동일해야 한다.
- `워터마크 적용` 후 결과 미리보기는 생성된 결과 Blob을 다시 decode해 표시한다. 설정 overlay만 보고 성공으로 처리하지 않는다.

## 10. EXIF 방향, 색상과 메타데이터

- EXIF Orientation 1~8을 화면에 보이는 방향으로 반영하고 결과에는 올바르게 지향된 픽셀을 저장한다.
- orientation을 중복 적용하지 않도록 decode 경로를 하나로 통일하고 corner fixture로 검증한다.
- Canvas 재인코딩 때문에 EXIF, GPS, 촬영 시각, ICC 등 원본 메타데이터가 제거되거나 달라질 수 있음을 실행 전에 안내한다.
- 원본 메타데이터 보존 기능은 V1에 포함하지 않는다.
- 색상은 브라우저 Canvas의 기본 sRGB 처리 범위를 따른다. Display P3·특수 ICC의 완전 보존을 보장하지 않는다.
- 픽셀 단위 원본 보존이나 무손실 편집을 주장하지 않는다.

## 11. 출력 형식과 품질

- 기본값 `원본 형식 유지`.
- JPEG 입력은 JPEG, PNG 입력은 PNG, WebP 입력은 WebP를 우선한다.
- 출력 선택: 원본 유지 / JPEG / PNG / WebP.
- JPEG/WebP 품질: 10%~100%, 기본 92%.
- PNG에서는 품질 slider가 파일 크기나 화질에 영향을 준다고 표현하지 않고 비활성화한다.
- 투명한 원본 또는 워터마크를 JPEG로 출력하면 투명 영역에 흰 배경이 적용된다고 실행 전에 알린다.
- WebP encoder를 지원하지 않는 브라우저에서는 MIME fallback을 검사하고 PNG 또는 JPEG 선택을 안내한다.
- 결과가 원본보다 커질 수 있으며 이를 오류나 거짓 절감으로 표시하지 않는다.

### 다운로드 파일명

- 기본: `{원본명}-watermarked.{실제확장자}`
- 예: `photo.jpg` → `photo-watermarked.jpg`
- basename이 비면 `watermarked-image` 사용
- 경로 구분자, 제어문자, Windows 예약 문자와 끝의 점·공백 제거
- Blob MIME, signature와 확장자가 일치해야 한다.

13. 사용 방법, 제한사항, 개인정보 설명, FAQ, 관련 도구

설정 패널은 첨부 화면처럼 짧은 흐름을 유지하되 다음을 개선한다.

- 색상 swatch와 HEX 입력을 하나의 명확한 field group으로 묶는다.
- range 현재 값을 항상 텍스트와 number input으로 함께 표시한다.
- 선택된 위치는 색상뿐 아니라 `aria-pressed`와 아이콘·텍스트로 구분한다.
- `워터마크 적용`과 `다운로드`를 분리하고, 적용 전에는 다운로드를 비활성화한다.
- 원본 교체와 전체 초기화를 구분한다.
- 결과가 현재 설정과 다른 경우 `설정이 변경되었습니다. 다시 적용하세요.`를 표시한다.
- 모바일에서 하단 고정 버튼이 콘텐츠를 가리지 않도록 한다. 고정 CTA는 필수가 아니다.

## 13. 상태 모델과 동시성

`empty → validating → ready → rendering → success | warning | error`

- 설정 변경: `success → dirty`
- 새 원본 선택: 이전 원본·결과·오류·Object URL·작업 generation 폐기
- 워터마크 이미지 교체: 이전 워터마크 bitmap과 Object URL 정리
- rendering 중 중복 실행 방지
- Canvas API 자체는 완전 취소가 어려우므로 generation id로 오래된 결과 반영을 차단한다.
- 적용 중 설정이 바뀌면 완료 결과를 현재 설정 결과로 표시하지 않는다.
- Object URL은 교체·초기화·unmount에서 revoke한다.
- 사용이 끝난 ImageBitmap은 `close()`하고 Canvas backing store는 `width=0`, `height=0`으로 해제한다.
- Data URL을 사용하지 않고 Blob/Object URL을 사용한다.

## 15. 개인정보와 보안

- 원본 File, 워터마크 File, bitmap, Canvas, 결과 Blob은 현재 탭 안에서만 처리한다.
- fetch, XHR, Server Action, API route, WebSocket, Beacon으로 파일 내용을 전송하지 않는다.
- localStorage, sessionStorage, IndexedDB, cookie, URL query/hash에 이미지나 설정을 저장하지 않는다.
- 페이지 방문 집계에는 도구 slug만 포함하고 파일명·텍스트·색상·설정을 포함하지 않는다.
- 이미지 워터마크 파일명은 UI에서 text node로만 표시한다.
- Canvas는 외부 URL 이미지를 사용하지 않아 tainted canvas가 발생하지 않게 한다.
- 사용자는 사용 권한이 있는 로고·사진을 사용해야 한다는 안내를 상세 콘텐츠에 포함한다.

## 16. 접근성 및 반응형

- 모든 file input은 visible label 또는 연결된 accessible name을 가진다.
- tab은 적절한 tab semantics 또는 명확한 radio group으로 구현한다.
- 위치 버튼 9개는 키보드로 접근 가능하고 현재 선택을 읽을 수 있어야 한다.
- range에는 label, 현재 값, min/max, 연결된 number input을 제공한다.
- 처리 상태는 `aria-live="polite"`, 오류는 `role="alert"`로 전달한다.
- 미리보기만으로 상태를 전달하지 않고 텍스트로 현재 설정과 결과를 요약한다.
- 색상 대비가 낮은 워터마크는 허용하되 UI control 자체의 대비는 WCAG 기준을 따른다.
- 320, 375, 768, 1024, 1440px에서 문서 가로 overflow, 설정 겹침, 버튼 잘림이 없어야 한다.
- 긴 파일명과 긴 워터마크 텍스트가 설정 패널 폭을 늘리지 않아야 한다.
- touch target은 최소 44×44px을 목표로 한다.

## 17. 성능과 메모리 기준

- 미리보기는 긴 변 최대 1,600px 이내의 별도 축소 Canvas를 사용한다.
- 다운로드 결과는 원본 해상도로 한 번만 렌더링한다.
- 원본 전체 해상도 Canvas와 미리보기 Canvas를 불필요하게 여러 개 유지하지 않는다.
- 12MP 일반 이미지 기본 설정은 최신 안정 Chrome warm run 기준 2초 이내를 목표로 한다.
- 24MP 경계 이미지는 10초 이내 완료 또는 명확한 진행 상태를 제공해야 한다.
- 반복 워터마크는 타일 수 상한 2,000개 및 최소 간격을 적용한다.
- 빠른 slider 변경마다 원본 해상도 렌더링하지 않고 미리보기만 갱신한다.
- 실제 결과는 명시적 `워터마크 적용`에서만 생성한다.
- 메인 스레드 장시간 정지가 확인되면 OffscreenCanvas/Web Worker 전환을 별도 Architect 검토한다.

## 21. 수용 기준

1. 텍스트와 이미지 워터마크를 각각 정상 적용할 수 있다.
2. 기본 예시 설정만으로도 워터마크가 눈에 보이고 이미지 밖으로 잘리지 않는다.
3. 크기·색상·불투명도·회전·여백·위치 설정이 미리보기와 결과에 일치한다.
4. 9개 위치가 가로·세로 이미지에서 모두 올바르게 동작한다.
5. 반복 모드가 브라우저를 멈추지 않고 이미지 전체를 채운다.
6. 이미지 워터마크의 종횡비와 alpha가 유지된다.
7. 결과는 원본 해상도를 유지하고 정상 decode된다.
8. JPEG, PNG, WebP 출력 MIME과 확장자가 일치한다.
9. 설정 변경 후 오래된 결과를 현재 결과로 다운로드할 수 없다.
10. EXIF 방향이 결과에서 잘못 회전되거나 뒤집히지 않는다.
11. 메타데이터·색상·손실 재인코딩의 제한을 실행 전에 안내한다.
12. 입력 이미지와 워터마크가 서버·외부 API·storage로 전송되지 않는다.
13. 모든 설정과 다운로드를 키보드와 보조기술로 사용할 수 있다.
14. 모바일에서 미리보기·설정·적용·다운로드가 자연스럽게 이어진다.
15. 기존 테마와 공통 도구 페이지 디자인을 유지한다.
16. 한국어·영어·일본어 메뉴, 홈 검색, sitemap과 상세 콘텐츠가 연결된다.
17. lint, type-check, 전체 테스트와 production build가 통과한다.
