# 프로젝트 목표

## 미션

로그인 없이 즉시 사용할 수 있는 빠르고 가벼운 웹 유틸리티를 한국어·영어·일본어로 제공한다. 각 도구는 독립 URL을 가지며, 개인정보와 비용을 줄이기 위해 가능한 처리를 브라우저 안에서 끝낸다.

## 성공 원칙

1. 사용자는 설명을 읽지 않아도 핵심 작업을 완료할 수 있어야 한다.
2. 모바일 환경을 우선하며 데스크톱에서도 자연스럽게 확장되어야 한다.
3. 첫 진입과 반복 사용이 빨라야 한다. 불필요한 의존성·서버 호출·추적 코드를 넣지 않는다.
4. 모든 사용자 문구와 SEO 메타데이터는 `ko`, `en`, `ja`로 확장 가능해야 한다.
5. 도구별 독립 URL과 검색 의도를 반영한 메타데이터를 제공한다.
6. 완성은 구현 종료가 아니라 품질 게이트 통과를 의미한다.

## 완료 정의

기능은 아래 조건을 모두 만족할 때만 `DONE`이다.

- 평가 총점 90/100 이상
- Critical 이슈 0개, High 이슈 0개
- SPEC 승인 시 확정한 필수 자동 검사와 테스트가 미실행·skip 없이 전부 PASS
- 브라우저 Console Error 0개
- 320/375/768/1280px 검수에서 핵심 흐름, 터치, 레이아웃 기준 전부 PASS
- 요구사항 및 수용 기준 충족
- 접근성·다국어·SEO·성능 점검 완료

최초 구현 평가는 회차 0이며 개선 횟수에 포함하지 않는다. 평가 결과에 따른 Optimizer 개선은 최대 5회 수행한다. 5회차 수정 후 Critic과 QA의 최종 재검증에서도 하나라도 미달이면 예외 승인으로 통과시키지 않고 `NEEDS HUMAN REVIEW`로 기록한다.

## 비목표

- 로그인, 계정, 사용자 데이터 동기화
- 브라우저에서 충분히 가능한 작업을 위한 서버 또는 데이터베이스
- 초기 검증 전의 대규모 도구 묶음
- 목적 없는 애니메이션, 무거운 UI 프레임워크, 과도한 분석 도구
- 운영 문서 없이 이루어지는 임의 기능 확장

## 운영 상태

`IDEA → CANDIDATE → SPEC READY → BUILDING → EVALUATING → IMPROVING → DONE`

품질 게이트 미달이며 5회를 소진한 경우 마지막 상태는 `NEEDS HUMAN REVIEW`다. 상태와 근거는 `PROGRESS.md`에 남긴다.
