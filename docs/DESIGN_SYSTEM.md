# 디자인 시스템

## 원칙

모바일 우선, 높은 가독성, 명확한 작업 순서, 즉각적인 피드백을 우선한다. 장식보다 작업 완료 속도를 중시하고 기존 Tailwind 토큰과 공통 UI를 재사용한다.

## 화면 구조

도구 페이지의 기본 순서는 제목/짧은 설명 → 입력 → 주요 실행 버튼 → 결과 → 복사·다운로드 등 후속 행동 → 도움말/개인정보 안내다. 핵심 작업은 첫 모바일 화면에서 식별 가능해야 한다.

## UI 규칙

- 320px 너비부터 가로 스크롤 없이 동작한다.
- 터치 대상은 가급적 최소 44×44px, 대상 간 간격을 확보한다.
- 본문은 읽기 쉬운 크기와 행간을 사용하고 긴 번역에도 레이아웃이 깨지지 않게 한다.
- primary action은 화면당 명확히 하나로 두며 동사형 레이블을 쓴다.
- 색상만으로 상태를 전달하지 않고 텍스트·아이콘을 함께 쓴다.
- 입력에는 시각적 label, 설명, 오류 연결을 제공한다. placeholder를 label로 대체하지 않는다.
- 키보드 focus를 숨기지 않으며 자연스러운 탭 순서를 유지한다.
- empty, editing, processing, success, error, disabled 상태를 설계한다.
- 결과는 복사 가능하고 성공/실패 피드백은 스크린 리더에도 전달한다.
- 애니메이션은 기능 이해에 필요할 때만 쓰며 reduced-motion을 존중한다.

## 문구와 다국어

짧고 구체적인 문장을 사용한다. 오류 문구는 문제와 해결 방법을 함께 말한다. 문자열 결합으로 문장을 만들지 말고 언어별 완전한 메시지를 사용한다. 한국어·영어·일본어에서 버튼 폭, 줄바꿈, 숫자/날짜 형식을 검증한다.

## 접근성 기준

시맨틱 HTML을 우선하고 ARIA는 필요한 경우에만 보완한다. 텍스트 대비는 WCAG AA를 목표로 한다. 모든 기능은 키보드로 수행 가능해야 하며 동적 결과와 오류는 적절한 live region 또는 focus 이동으로 인지 가능해야 한다.

## 디자인 검수

최소 320px, 375px, 768px, 1280px에서 확인하고, 밝은 테마 기준의 focus·hover·active·disabled·error 상태를 검토한다. 향후 다크 테마는 별도 SPEC 없이는 범위에 포함하지 않는다.
